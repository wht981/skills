# 可展开的知识地图

把大型主题呈现为可导航的领域地图，而不是课程、学习计划或一次性展开的百科全书。地图描述概念本身的结构，帮助用户从全局逐层缩放到感兴趣的细节。

## 从根层开始

先确认主题和本次地图的边界，包括要覆盖的子领域与明确排除的相邻领域。给出根节点的直接子节点和它们的简短作用说明，不自动继续向下展开。

每次只显示当前节点的一层直接子节点，同时标出必要的跨节点关系。让用户选择要展开的节点。用户也可以直接指定节点、展开层数，或要求“展开到最底层”。后两种情形下，沿指定分支连续展开，不必每层停下来确认。

将节点拆到当前地图范围内的最小结构单元为止：它表达一个独立概念、机制或操作，继续拆分只会进入实现细节、术语定义或超出范围的相邻领域。这个边界服务于地图，不声称概念在理论上不可再分。

## 表达结构

为节点分配稳定 ID。标题可以随表述改善，但 ID 应保持不变，以便父子关系和跨节点引用稳定。

区分层级包含关系与跨节点关系。跨节点关系至少使用 `前置依赖`、`推荐关联` 和 `应用分支`，不要把所有连接都伪装成严格的学习顺序。节点文件应显示父级入口、直接子节点和与其他节点的关系，使每一层都能独立阅读和继续导航。

图谱是索引，不是概念讲义。节点说明应足以让用户决定是否继续展开，完整解释只在用户另行要求时提供。不要预先将模糊领域切成大量假精确的节点。

涉及版本、生态约定或有争议的结构判断时，优先核实官方文档或其他一手来源，并按需引用来源。不要把模型记忆当作这类事实的唯一依据。

## 可选持久化

默认在对话中展示地图，不创建文件。用户明确要求保存或维护地图时，先确认目标工作区和主题别名，然后在其中创建或维护 `knowledge-map-<topic-slug>/`，例如 `knowledge-map-typescript/`。运行时生成的所有地图文件必须位于这个目录内。

创建前检查同名目录。兼容的既有地图应读取并更新，不能清空或重建。若目录无法识别、属于另一主题或会覆盖用户文件，暂停并请用户选择处理方式。发现旧式 `learning-map-*` 或 `learning_map/` 时可以读取并建议迁移，但绝不自动改名、移动、合并或删除。

保存递归地图时，阅读 [知识地图格式](./references/learning-map-format.md)。只有用户选择或明确要求展开的节点才创建对应的节点文件。项目代码、个人学习进度、练习、课程材料和学习记录不属于知识地图。

## 边界

若用户需要个人学习计划、跨会话进度或课程材料，建议使用 `$teach`。若用户已经选定一组能力并希望用项目整合实践，建议使用 `$stage-proj-teaching`。本技能只负责建立和导航领域知识结构。
